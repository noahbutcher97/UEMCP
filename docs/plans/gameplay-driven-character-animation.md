# Gameplay-driven character animation

The delivery target is an agent that can build and revise a playable character from a gameplay brief. A single character should use authored clips for the performance, procedural controls for live targets, and gameplay state to determine how those contributions combine. The reference task below is a proposed fixture. Its particular interaction, skeleton and bone names can be exchanged for project assets.

## First playable task

> Use the supplied character, idle and walk cycles, and authored reach clip. Let me walk up to a moving handle. While I hold Interact, keep walking, play the reach with my upper body and make my right hand follow the handle. Letting go, losing the handle or being staggered should release the hand. After a stagger, return to the right locomotion for my current speed.

Start in an owned project with a possessable character, compatible clips and a moving prop. Publish exactly what is prebuilt, including any movement or input bindings. The fixture may supply and instrument the gameplay events. The agent must author the connections covered by the task through the public UEMCP client. A prewired AnimBP, a probe that implements the missing gameplay behavior, or directly setting reach alpha would invalidate the end-to-end result.

| Who owns the decision | Design for this character | What to observe |
| --- | --- | --- |
| Player controller and character | Movement input requests motion. Held Interact expresses intent. Gameplay decides whether a valid target is in range and whether stagger interrupts. After cancellation, require a fresh press for this example. | Record press and release, target acquisition or loss, accepted interaction, interruption and movement velocity on the possessed pawn. |
| Authored animation | Actual ground speed drives idle/walk. Cache the base pose. Overlay the reach montage on the upper body while the locomotion cycle advances. A stagger takes full-body priority. | Match lower-body phase against locomotion alone. Sample the authored torso movement and the transition into and out of stagger. |
| Procedural animation | After the authored reach, solve the reaching arm toward the moving handle. Snapshot the target transform from gameplay, convert it to the solver's declared space, and drive IK weight from interaction state. Fade out on release or target loss. | Compare the evaluated hand and handle in world space, including while the character turns. Repeat with IK disabled and check the arm follows the authored pose. |

Start with a Two Bone IK implementation for the reference arm. A later variant can substitute a compatible Control Rig or add a separate foot-placement pass without changing the gameplay task. Make bone chains, spaces, masks and evaluation order discoverable to the agent. Unreal's Two Bone IK exposes both an effector and a joint target. [Epic Two Bone IK reference](https://dev.epicgames.com/documentation/unreal-engine/animation-blueprint-two-bone-ik-in-unreal-engine)

## What the first agent experiment must establish

- **Gameplay binding.** The public catalog includes Enhanced Input action, context and key-mapping creation. Its named input-event node writer explicitly targets legacy Input Actions. Check context activation on the possessed player, Enhanced Input event binding and propagation to the AnimInstance separately. Try the existing public Blueprint operations before proposing another writer. Record the first blocked operation and the agent's recovery. [Tool contracts](../../tools.yaml)
- **Pose composition.** The merged foundation includes sequence-backed states, numeric transitions, cached poses, explicit rewiring and Slot insertion. Its contextual node-placement handler selects a two-way blend. Discover the procedures available for a branch-filtered upper-body layer, local/component-space conversions and a configured arm solver on the target installation. Verify any candidate by evaluating it. [Animation handler](../../plugin/UEMCP/Source/UEMCP/Private/AnimationHandlers.cpp) and [owned fixture](../../server/fixtures/interactive-animbp/README.md)
- **Useful first increment.** Run the full prompt against the baseline. Then establish the smallest playable loop in which a player action and a gameplay condition jointly control an authored pose and one procedural target on the same pawn. Add overlap with locomotion, interruption and replay on that same character. Each increment should leave a character that can be possessed and exercised.

## Acceptance in an owned editor

1. Start PIE and replay the same movement, turn, interaction and interruption timeline at fixed sample times. Cover stationary and moving cases, a reachable moving target, release while walking, target destruction while held, and stagger during the reach. Use a mapped key press/release in at least one run. Enhanced Input action injection can support deterministic repeats. Record which path ran because injecting an action bypasses physical key mapping. [Epic input injection reference](https://dev.epicgames.com/documentation/unreal-engine/BlueprintAPI/Input/InjectInputforAction?lang=en-US)
2. Before running the authored result, capture locomotion-only and authored-reach-without-IK controls. Choose a reachable handle trajectory that measurably diverges from the uncorrected hand. Sample actual mesh bones, montage state, IK weight, target transform and the gameplay events on the same timeline. Proposed fixture targets are hand error within 2 cm after settling and excluded lower-body bones within 1 cm and 2 degrees of the phase-matched base in parent-local space. Calibrate the controls and record blend windows before judging the result. Check a rotating character so an accidental world/component-space match cannot pass.
3. Verify interruption releases the constraint, stagger can take over while Interact remains held, and recovery follows current velocity. An invalid chain, missing target or incompatible clip should leave a diagnosable state. Undo and redo an authoring change, save named packages, reopen in a new editor and replay. Record graph links, asset references, dirty packages and evaluated motion independently of the agent's answer.
4. Time a cold build from the gameplay prompt. Then ask a fresh agent to reuse the setup on a second owned character with different clip and bone names, change the reaching hand, and resume after an interruption. Use explicit roles for clips, bones, inputs and targets. Preview which assets will change, preserve unrelated edits, and verify a retry leaves one binding and one layer. Report time to first playable result and time to a verified variation, MCP calls, clarification turns and manual fixes. These measurements establish what “quickly” means before setting a speed target.

This is a design for agent-driven acceptance. Start on UE 5.8.4 and record a separate result for every further engine or provider exercised. Observed human usability follows the agent-tested authoring milestones. The broader program retains sequence editing, rig authoring, retargeting and baking as additional workflows.
