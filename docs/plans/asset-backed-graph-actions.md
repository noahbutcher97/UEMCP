# Discovering and placing asset-backed graph nodes

**Proposed first delivery.** An agent can bind a pawn to a named Enhanced Input action or play a named sequence in an AnimBP by discovering and invoking the same contextual action Unreal offers in the graph editor. The two operations share discovery, placement and Undo. Each family supplies its own compatibility check and verifies the referenced asset on the placed node.

## Why the asset belongs in the action identity

On UE 5.8.4, a CLI agent asked to bind a mapped action through public UEMCP tools could create a generic event that compiled with zero errors. A fresh Unreal process found no Enhanced Input event on the pawn. The legacy writer produced a legacy node. The failure occurred before possession or gameplay dispatch. [Input binding qualification](gameplay-driven-character-animation.md#current-public-authoring-coverage)

The installed engine source identifies a reusable mechanism. In `UK2Node_EnhancedInputAction::GetMenuActions`, Unreal registers a spawner for each input action and sets the new node's `InputAction` reference. For a Sequence Player, `UAnimGraphNode_AssetPlayerBase::GetMenuActionsHelper` registers asset data with a spawner and applies asset-specific initialization. The helper also supports an empty player. An empty player, a player for Walk and a player for Run can share a class. UEMCP's existing two-way-blend discovery returns that class path as the action identifier. [Current discovery and placement](../../plugin/UEMCP/Source/UEMCP/Private/AnimationHandlers.cpp)

## Proposed public contract

| Operation | Agent supplies | Agent receives |
| --- | --- | --- |
| `find_graph_actions` (read) | Target Blueprint package and graph name or GUID. Optionally an exact source asset path or a search term such as “Interact”. | Resolved graph GUID and topology revision. A bounded list of supported matches with action ID, family, display name and full source asset path. Indicate truncation and distinguish incomplete registry discovery from a complete search with zero matches. Ambiguous graph names return graph choices. |
| `place_graph_action` (edit) | Target Blueprint package, graph GUID, expected revision, action ID from discovery and node position. | Whether a node was created or reused, its GUID and class, the asset reference read from the node, actual pin IDs/types/directions, resulting revision, and dirty packages. Wiring, compile and save remain explicit steps. |

For example, two results labeled `IA_Interact` in different folders must show both paths. The client can refine by exact path or ask which asset the user intended. A placement request carries the selected ID. The server must never resolve a mutation by taking the first display-name match.

For an exact asset query, also return matching nodes already placed in that graph with their GUIDs, positions and observed references. This gives pawn Event Graph callers the same retry check as AnimGraph callers. After a timeout, compare these GUIDs with the pre-edit set. If concurrent edits leave multiple plausible new nodes, return the candidates for inspection.

The ID is opaque to clients. Resolve it against the current editor session, target graph, action family, canonical source object and action variant. Recheck the context on the editor game thread immediately before invoking. Use the action's actual registration owner when filtering. Reject stale, ambiguous, incompatible and read-only targets before opening a transaction. A graph revision alone cannot detect every source asset change. Re-resolve the asset, check compatibility, and reject an expired selection after rename, replacement or editor restart. A stale response should give the arguments needed to rediscover.

Use the existing editor transaction and graph revision helpers. Verify that the returned node belongs to the target graph's node list, references the exact selected asset and exposes the family's expected pins. Record any unexpected changes if verification fails after invocation, including whether Undo can restore the previous graph. A cancelled transaction alone is insufficient evidence of rollback. If a reply is lost, refresh graph membership and inspect node GUIDs and asset references before retrying. Multiple Sequence Players can legitimately reference the same clip.

Keep the legacy input writer's action-name argument and the two-way-blend writer's class-path argument. The proposed interface will advertise each new family once its acceptance cases pass.

## Impact and adoption decisions

| Surface | Decision and reason |
| --- | --- |
| Pawn Event Graph and top-level AnimGraph | Adopt both operations here first. Implement one native context resolver, graph membership check and transaction path. The input family reads the bound `UInputAction` and actual trigger/value pins. The player family reads the effective sequence, Skeleton compatibility and pose output. Match the writable target graph and its schema explicitly. Function graphs, transition rules and nested states need their own context tests before becoming placement targets. |
| Existing two-way blend | Keep `get_anim_graph(include_actions=true)` and `place_anim_graph_node` interoperable with existing clients. The former returns class-path strings and the latter accepts those strings and an optional alpha. Introduce shared internal plumbing only when the old discover → place → wire test passes with its original payloads and responses. The new discovery results have their own schema. [Current implementation](../../plugin/UEMCP/Source/UEMCP/Private/AnimationHandlers.cpp) |
| Legacy input, ordinary events and function calls | Keep their native semantics. At release, update help and search aliases so a request mentioning an Enhanced Input asset leads to graph-action discovery. The legacy node still serves projects using named legacy mappings. Ordinary event callers still need reflected overrides and reuse of existing auto-placed events. A successful generic event is never evidence of a bound Enhanced Input asset. |
| State, transition, Slot and cache tools | Keep their higher-level writers. In particular, `add_anim_state` already creates a child graph, sets its Sequence Player, wires its sink and optionally connects the entry in one edit. A state can reuse the player's reference/compatibility verification, but routing it through a second public placement would split Undo and failure handling. Slot insertion owns a displaced edge; cached-pose uses own a Save-node GUID. Their identities and atomic edits remain with those tools. [State authoring](../../plugin/UEMCP/Source/UEMCP/Private/StateAuthoring.cpp) · [Slot insertion](../../plugin/UEMCP/Source/UEMCP/Private/AnimSlotInsertion.cpp) |
| Graph consumers | Return node and pin IDs in the same representation consumed by `connect_nodes`, `show_pin_links` and `disconnect_pin`. Use the effective graph GUID and current revision from each edit. Verify a newly placed output can replace an occupied source with one Undo for replacement and a separate Undo for placement. Re-read pins after reconstruction. [Revision and pin helpers](../../plugin/UEMCP/Source/UEMCP/Private/BlueprintHandlerHelpers.cpp) |
| Other graph families | Bone controls, layered blending, linked Anim Layers and Control Rig nodes are candidates for the same discovery interface as individual families earn support. Their configuration and evaluated result need family-specific checks. Material expressions, widget layout, montage/sequence timelines, rig hierarchies and asset factories retain their domain writers. A graph-like editor UI alone does not establish that Blueprint node spawners implement those edits. |
| Recipes, offline inspection and replay | Persist the Blueprint locator, graph role, family, source asset path and desired wiring in recipes. Resolve a fresh action ID on each live execution. Offline snapshots can describe intent; expose an editor-required result when live actions cannot be resolved. Headless placement needs separate qualification. [Execution modes](animation-authoring-execution.md) |

### Discovery, deployment and editor lifecycle

**Graph targeting is an implementation dependency.** Today `connect_nodes` accepts a graph GUID but its GUID branch explicitly requires a `UAnimBlueprint`. Passing the discovered pawn Event Graph GUID to it would return `UNSUPPORTED_GRAPH`. The name-based resolver can also call `FindOrCreateEventGraph`, which is inappropriate for discovery on an asset missing that graph. Provide a lookup-only resolver for the two target contexts. Extend GUID wiring to the pawn's owned Event Graph, and add an optional matching GUID to `show_pin_links` and `disconnect_pin` for that same round trip. Include graph and pin names alongside GUIDs because existing wiring payloads require names. Preserve name-only callers; reject a name/GUID mismatch. Test that reading an absent graph leaves the Blueprint and package untouched. [Current resolver and callers](../../plugin/UEMCP/Source/UEMCP/Private/BlueprintHandlers.cpp)

- Register discovery once in `blueprint-read` as a live read and placement once in `blueprints-write` as a live asset mutation. Include input and animation vocabulary in the catalog and existing toolset guidance. Both direct tools and the `describe_tool` dispatcher route must agree on schema, project and editor identity, and mutation permissions. A read-only client can discover and inspect. Only an authorized writer can invoke. [Tool requirements](../../server/tool-requirements.mjs) · [Dispatch](../../server/tool-dispatch.mjs)
- The existing [search index](../../server/tool-index.mjs), run against the merged catalog, ranked `add_input_action_node` first for “bind Enhanced Input action to pawn” and `bp_list_graphs` first for “play animation sequence in AnimGraph”. At release, require the appropriate discovery tool in the first three results for both prompts, and make the Enhanced Input path rank ahead of the legacy writer for the first prompt. Test a legacy-input prompt as a control. Update the [widgets guidance](../../server/server-guidance.mjs), which currently sends Enhanced Input users only to the asset-creation toolset.
- A session action ID belongs to its verified editor, project attachment generation and graph. Reattachment or an editor restart requires rediscovery. For Undo/Redo, asset rename/replacement, registry refresh and Blueprint recompilation, re-resolve the semantic selection before invoking. Discard cached spawner pointers after invalidation. `GraphTopologyRevision` includes pins, links and selected cache/Slot state; it does not currently fingerprint these two asset references. Validate the source independently, including a same-path replacement after discovery. Discovery must avoid dirtying packages and cap work as well as result size. Prefer exact-asset lookup; test broad searches during registry loading and avoid loading an entire project's animations just to return a page.
- Check the installed plugin response separately from the server's catalog. If an older editor plugin returns `UNKNOWN_COMMAND`, surface the version/deployment diagnostic and the sync/rebuild/restart recovery. Preserve the legacy tools supported by that editor. Keep unavailable or unqualified families out of the placeable results. Check editor module dependencies for the Enhanced Input graph node separately from the existing runtime `EnhancedInput` dependency. Stage new native files in the fixture staging allowlist and run packaging per claimed engine.

### Duplicate placements and interrupted requests

For an Enhanced Input event, return an existing exact match as `reused` only when its live graph membership, event kind, bound asset and required pins match. Report multiple existing matches for selection; leave their wiring intact. Two Sequence Players for the same clip can legitimately have different wiring and playback settings. An explicit placement creates another player. A retry after a lost response first compares the exact-asset node set with the pre-edit set. If another client placed an equivalent node concurrently, report the ambiguity with node GUIDs. Never infer ownership from asset and position alone. A reused result adds no Undo entry.

Alongside the two live tasks below, test refusal with an old revision, the same ID against a different Blueprint, an attached project switch, immediate Undo/Redo, and a lost reply after a successful edit. Compare graph membership, asset references, edges and dirty packages. Test the MCP catalog, direct/dispatcher parity and old payloads with the server rotation. Use real Codex and Claude prompts for discovery and placement and report provider/engine coverage individually. The two proposed tools remain design-only until implementation and owned-editor acceptance.

## Existing writers that can report a different result than requested

On November 21 the public MCP server at `c15aec3` authored one Actor Blueprint and one single-segment montage in an owned UE 5.8.4 editor (CL 58902052). The Blueprint compiled with zero errors and warnings and both assets saved. A second editor opened the saved packages. Unreal Python invoked each function on a transient actor, resetting its scale to unit before each call. Unreal's native text exporter independently exposed the montage's section and notify links.

| Public request | Control and observed result after reopening | Required behavior |
| --- | --- | --- |
| `add_function_node` with a misspelled input | Calling `SetActorScale3D` with `params.NewScale3D=[2,3,4]` produced scale (2,3,4). Changing only the key to `NewScale3` still succeeded and produced (0,0,0). | Validate every supplied key against the node's input pins before committing the edit. Return the invalid name and valid inputs. Verify the effective value of every accepted default. |
| `add_function_node` with an explicit nonexistent owner | Supplying `/Script/Engine.DoesNotExistProbe` for the same inherited function succeeded and scaled the receiving actor to (5,6,7). A missing member on that same owner returned an error. | Preserve implicit self lookup when the caller omits the owner. Reject an explicit owner that fails resolution, even if self has a compatible member. Return the resolved function identity on success. |
| `add_function_graph` with the name of another graph kind | Repeating a genuine function name returned its original entry GUID. Asking for `EventGraph` reported successful reuse and omitted the entry GUID. Invoking that name on the generated actor failed function lookup. | Require a function graph and its entry node before reporting reuse. Describe the conflicting graph and reject a kind collision without changing the asset. |
| `add_montage_section` and `add_montage_notify` beyond the end | On a 1.833333 s montage, a section at 0.916667 s and a PlaySound notify at 0.458333 s linked to the clip. Both writers also accepted 3.833333 s. The saved section and notify kept that time, with segment length −1 and no linked sequence. | Validate the requested position against the playable range before appending. Define endpoint behavior separately for sections and notifies. Test in-range, endpoint and out-of-range cases, then verify section traversal and notify delivery during playback. |

The pin lookup silently skips a missing input, the explicit class lookup falls back to the generated class, and the graph reuse branch accepts a name match across graph kinds. The same default-setting helper serves `add_variable_set`; exercise that caller when changing the helper. The live typo reproduction used the function writer. The montage writers append the requested time without an upper bound. [Blueprint handlers](../../plugin/UEMCP/Source/UEMCP/Private/BlueprintHandlers.cpp) · [Montage handlers](../../plugin/UEMCP/Source/UEMCP/Private/AnimationHandlers.cpp)

Apply exact target, kind and effective-value checks to the new graph actions and to repairs of those three existing Blueprint paths. Track montage timeline validation with animation authoring. Its acceptance depends on playable time and segment linkage, independently of graph placement. A negative request should leave graph membership, package dirty state and Undo history intact. Preserve the valid calls above as positive controls.

A fresh Codex CLI 0.171.0 session was given the asset path, the intended scale and the two function names. It recovered the effective pin values and self wiring through live `show_pin_links`. The offline reader found both call nodes but could not decode their pins. Two live reads initially returned `EDITOR_IDENTITY_UNKNOWN`; the agent followed the returned `connection_info(force_reconnect=true)` instruction and retried successfully. For the writer repair, repeat that task and check that the original edit reports the typo directly. This trial covered agent diagnosis. The actor calls ran in the editor world. PIE, montage playback, other engines, Claude and observed human use remain unexercised in this pass.

### Engine and CLI qualification

Repeating the four cases above on Win64 reproduced all four defects on UE 5.3.2 (CL 29314046), 5.6.1 (CL 44394996) and 5.8.4 (CL 58902052). In each fresh process, Unreal executed the valid, typo and wrong-owner functions with the same three distinct scales, rejected the `EventGraph` function lookup, and exported both late montage entries without a linked sequence. UE 5.6.1 crashed during the initial editor actor placement after saving both assets. The successful independent check used a fixture-only native helper to spawn the actor directly in the editor world. The plugin stayed at `c15aec3`. UE 5.7 is in the packaging matrix and its editor was unavailable locally.

An additional CLI task asked for the two scale literals without authorizing edits. On the 5.6.1 fixture the offline node reader returned both saved literals. Codex, Copilot and OpenCode used that route to deliver the correct diagnosis. On the 5.3.2 fixture, agents found the functions but failed to establish both values; a Grok session reported the intended value for both. On the 5.8.4 fixture, Claude reached both values through live reads but exceeded the initial 210-second trial before delivering its answer. In a separate OpenCode session, `regenerate_sidecar` actually wrote a sidecar during the requested inspection. That write did not change the saved Blueprint or montage hashes.

The offline-to-live handoff has a concrete identity defect. On UE 5.8.4, `bp_find_in_graph` returned `026b8919d537fb48933909c03d2cecc9` for the valid call node. `show_pin_links` rejected that GUID. The same request with Unreal's `19896b0248fb37d5c0093993c9ec2c3d` returned the expected vector. Both call nodes on 5.6.1 and 5.8.4 showed byte reversal within each of the four 32-bit words. On the 5.3.2 fixture the offline result omitted both call-node GUIDs. Preserve the distinction between the offline export index and the live node identity. [Offline node reader](../../server/offline-blueprint-tools.mjs) · [Binary reader](../../server/uasset-parser.mjs)

Make each public offline graph GUID reusable by the live reader. Check existing consumers of raw GUID bytes before changing serialization. Where parsing yields no GUID, identify that limitation and provide a live lookup by graph and node. Include the actual pin name and test that a fresh agent can finish this inspection without regenerating a sidecar. In a 5.8.4 retry, guidance to inspect the live inputs by GUID helped Codex and Claude deliver both correct values. Copilot and OpenCode still left the values unverified, and Grok reported the intended scale for both. Preserve those cases when testing a repair. [Agent workflow qualification](../agent-workflow-usability.md)

## First experiment and acceptance

Run the first native experiment in a UEMCP-owned editor using UE 5.8.4, with a pawn Event Graph and a top-level AnimGraph. Use two same-named source assets in different packages. Record the registry owner, contextual filter result, graph membership, bound asset and actual pins before and after invoking each selection. Repeat discovery immediately after creating a new source asset, then after renaming it. For Sequence Players include an incompatible Skeleton and distinguish the empty-player entry. This checks the native design premise before committing to an ID format or a particular registry lookup.

| Real CLI request | Independent acceptance |
| --- | --- |
| “While I hold Interact, set this pawn's Interacting flag. Clear it when I release.” | Start with an owned, possessed pawn and activated mapping context. Document that fixture setup. The agent places the event for the exact action and wires the relevant trigger outputs. Drive the mapped key through press and release in PIE and sample the pawn flag before, during and after. Exercise cancellation for a trigger configured to cancel. A different key/action leaves the flag unchanged. |
| “Use the Walk clip from this folder as the character's output. Keep the old player available.” | The agent places a Sequence Player for the named clip and explicitly rewires the occupied output. Read the asset reference and reciprocal pins independently. Compare evaluated bone motion against the two distinguishable source clips and confirm the old player remains. |

For both, verify placement Undo/Redo and named save followed by fresh-editor readback and replay. Exercise a stale selection without creating a duplicate. Record the plain-language prompts, discovery calls, retries, time to completion, editor version and unintended changes. Use the retained legacy/generic event result as the negative control. Report 5.3.2 and 5.6.1 separately when exercised. Observed human sessions come after agent-driven acceptance.

The first implementation decision follows the native probe: if both families can be resolved and placed from the same context, implement the shared resolver and the two readback checks. If either family needs a different registration path, keep the same client contract and document the engine-specific lookup demonstrated by the probe.
