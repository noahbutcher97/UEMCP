# Owned Blueprint discovery and inspection (T09b)

Run from `server/`, with no project attachment or installed Unreal Engine:

```sh
node run-rotation.mjs --test-profile owned-blueprint-query --json
```

The suite has 46 required named cases. Missing or invalid corpus data fails before
queries run; it never becomes a skipped consumer probe. The default rotation
discovers `test-*.mjs`, so it also picks up this suite automatically.
The `owned-blueprint-query` profile requires the exact 46 case names once each.
Missing, duplicate, skipped, unexpected or unsuccessful cases fail qualification,
even when the surrounding suite reports passes. Direct focused development runs
remain available with `node test-owned-blueprint-query.mjs`.

The profile binds four required inputs: the corpus manifest, UE oracle, saved
`BP_OwnedLink.uasset`, and
`server/fixtures/uemcp-fixture/Source/UEMCPFixture/AuthorSerializationFixtureCommandlet.cpp`.
The authoring source is explicit because the literal assertion depends on it;
missing source cannot silently leave an otherwise complete corpus qualified.
Evidence hashes all four inputs as raw bytes and binds them to the tested source
inventory, Git HEAD and dirty patch. The suite's historical authoring-provenance
check separately accepts LF/CRLF checkout equivalence; it does not normalize the
raw execution evidence or immutable asset/oracle hashes.

## Evidence and acceptance

This is partial coverage toward INV-112/160/270, not completion of those
invariants. All queries call the public `executeOfflineTool` dispatcher with the
explicit immutable `server/fixtures/serialization/ue5.6-owned-v1` root. The existing
verifier first checks corpus provenance, hashes, saved package identity, and
agreement with the independent UE reload oracle.

The suite checks:

- Exact graph, node and entry-point discovery for `OwnedGraph`, `OwnedPrint` and
  `OwnedEvent`, including class, GUID, authored member, position and target.
- Class, member, target and combined filters, unmatched/conflicting filters,
  member case sensitivity, ordered pages, exhaustion, totals and truncation,
  and filtering before pagination.
- Inspection by authored name and discovered numeric ID for both nodes, plus
  entry-point ID handoff; pin availability, all oracle pin names/directions and
  exact link endpoints in both directions.
- The authored `InString` literal `UEMCP owned serialization fixture`. The UE
  oracle does not record defaults: this expectation is independently grounded
  in `AuthorSerializationFixtureCommandlet.cpp`, whose content must match the
  recorded authoring source hash after normalizing checkout CRLF to LF. Both
  newline forms are tested; an actual source edit is rejected. The original
  manifest and immutable package/oracle byte hashes remain unchanged.
- Unknown graph/node rejection and negative controls for missing discovery,
  wrong GUID/total, dropped/renamed/reversed pins, dropped/wrong link endpoints,
  changed literal, edited authoring source, missing corpus, changed oracle bytes
  and invalid provenance.

The INV-160 pin-shape extension preserves the original 41 cases and four input
bindings, adding two positive cases and three mutation-control cases. Both owned
nodes are inspected against the existing oracle before the checks combine their
complete, nonempty twelve-pin inventory.

| Original INV-160 predicate | Owned extension | Remaining limit |
|---|---|---|
| Every `pin_kind` belongs to `exec`/`data` | All twelve pins satisfy that vocabulary; invalid and missing kinds are rejected on each individual pin | Does not prove which kind is semantically correct for a particular pin or arbitrary graph family |
| No pin has `default_object === null` | All twelve pins exclude null; injecting null on each individual pin is rejected | Does not prove property omission, object identity, or absence versus own-undefined fields |

Each mutation uses a response clone after its unchanged positive baseline passes.
This slice does not assert exact pin-kind classifications, object-property
omission, new default values, or autogenerated-default values. Original consumer
and package-specific assertions remain retained; INV-160 is still partial and no
test, fixture dependency, or execution lane is approved for retirement.

Negative controls require an intact positive baseline first. Response mutations
use clones; corpus mutations use temporary copies, cleaned in `finally`. Normal
execution neither regenerates expectations nor changes the checked-in corpus.
Oracle pin/link ordering is ignored; identities, multiplicity and endpoints are
compared exactly. Pin IDs qualify this immutable save/oracle pair only: a future
UE resave or pin reconstruction needs separate review. Numeric export IDs are
obtained through discovery instead of being pinned to incidental table offsets.
Discovery and inspection compare node GUIDs directly with Unreal's recorded
`FGuid::ToString(EGuidFormats::Digits)` values.

## Inspecting a saved graph through a live editor

Use `bp_find_in_graph` with the graph name. Take the matching row’s numeric
`node_id` into `bp_show_node` for a saved-file read. Its `node_guid` is the
32-digit engine identifier accepted by live Blueprint tools. When a node name
appears in two graphs, name-only inspection reports both qualified names and
export indices. Pass the intended numeric index to disambiguate. The generic
`node.properties.NodeGuid` field preserves its property-reader representation.

If `pin_block` is unavailable, an empty pin array leaves the pin count and
values unknown. For graph nodes, `bp_show_node.live_pin_lookup` supplies the
exact `show_pin_links` arguments for an attached editor. Omit `pin` to list
current pins, types and literal defaults. Supply a pin name to inspect its
connections. If saved identity is missing, the lookup uses the exact graph and
node object names. Literal text pins expose their current display string in
`default_text_value`. Both live reads work without generating a sidecar.

A project-relative disk path inside Content resolves to its extensionless `/Game`
package. The live Blueprint resolver requires game content. An inspected asset
outside that mount returns `live_pin_lookup_unavailable` with the reason.

## Explicit qualification limits

**Graph-type classification is excluded.** The authoring commandlet uses
`AddUbergraphPage` for `OwnedGraph`, while the current offline discovery heuristic
reports `function`. Assertions deliberately omit `graph_type` and
`outer_graph_type`; they do not bless this label or claim correct ubergraph
classification. Production behavior is unchanged.

One UE 5.6 package with two nodes and one execution connection cannot qualify
branching, cycles, self-loops, data-flow traversal, comments/containment,
AnimBlueprints, arbitrary graph families, GUID-as-input lookup, genuine old-engine
packages, or general consumer compatibility. Existing synthetic, consumer and
legacy compatibility witnesses remain necessary and unchanged. This engine-free
suite is not native handler or runtime qualification and runs no Unreal process.

Required-profile integration uses the existing rotation and execution-evidence
validator. The production dispatcher, authoring source and immutable corpus remain
unchanged. A passing profile establishes the bounded cases above;
it does not complete INV-112/160/270 or replace retained synthetic, consumer,
legacy or native coverage.


## Inspect the arguments of a Blueprint function call

Call `inspect_blueprint_inputs` with a Blueprint path and the name of its graph. For example, inspect a scale call with

```json
{
  "asset_path": "/Game/Example/BP_Character",
  "graph_name": "SetSize",
  "member_name": "SetActorScale3D",
  "pin": "NewScale3D"
}
```

A graph containing a single saved `K2Node_CallFunction` needs only `asset_path` and `graph_name`. Omit `pin` to see all inputs. Specify `member_name` to narrow the selection. If several calls match, select the desired numeric export index from `saved.candidates` with `node_id`. `bp_find_in_graph` and `bp_show_node` supply a ready-to-use `input_inspection` for a specific call.

The default `compare` mode returns two observations. `saved` comes from the selected export’s pin block on disk. `live` comes from the current editor after a fresh read-only project identity handshake, using that saved node’s Unreal GUID and graph name. The operation can reveal an unsaved pin change on that node. Each source retains its own status and literal encoding. Different text formatting alone does not establish a change. `source: "saved"` performs the package read without contacting the editor. Neither mode saves, compiles, regenerates sidecars, changes project attachment or runs a function.

Each observed input reports its stored default and whether it is linked. For a linked input, follow the connection to understand where the argument comes from. The stored default is dormant while the link is active. A named pin read includes its endpoints. An all-pins live read supplies `inspect_links` arguments for connected inputs. A missing serialized default is represented by null. `autogenerated_default`, when present, is reported separately.

If a package layout cannot be decoded, `saved.status` remains `pin_data_unavailable` even when a live input is readable. Other statuses identify a missing graph, ambiguous call, unsupported live mount, missing saved GUID or unavailable editor. Live-only additions require a separate editor graph query because discovery here begins with the saved call. `runtime` remains `not_evaluated` across all observations.

The earlier full-prompt UE 5.8.4 trials showed the limits of passing a saved node ID to a second tool. One client stopped before verifying editor identity. Another used Find in Blueprints search metadata as function arguments. This operation performs the scoped lookup and handshake in one read while keeping the source of each observation visible. The existing saved export and live link queries remain useful for full property metadata and deeper graph traversal.
